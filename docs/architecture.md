# Архитектура

## Ответственность модулей

| Модуль | Назначение |
|---|---|
| `cli.py`, `__main__.py` | Аргументы и завершение команды |
| `bootstrap.py` | Сборка зависимостей и владение ресурсами |
| `config.py` | Настройки и пути к данным |
| `polling.py` | Получение обновлений и обслуживание очереди |
| `conversation/routing.py` | Типизированное решение LLM, музыкальные параметры, строгая проверка JSON и повтор |
| `conversation/service.py` | Решение об ответе, интервалы, очередь, отправка |
| `conversation/context.py` | Построение контекста из сообщений |
| `conversation/ports.py` | Структурные контракты зависимостей |
| `generation/service.py` | Получение нот/аранжировки, валидация и повторы |
| `generation/prompts.py` | Типизированный каталог, загрузка и проверка шаблонов |
| `resources/prompts.toml` | Все инструкции модели, персонаж и проверочные запросы |
| `integrations/` | Telegram и OpenClaw |
| `storage/` | SQLite и сохранение интервалов |
| `audio/jobs.py` | Запуск и остановка аудиопроцесса |
| `audio/worker.py` | Проверка задания на границе процесса |
| `audio/pipeline.py` | Последовательность создания аудио |
| `audio/composers.py` | Стратегии: готовая партитура и NanoMaestro |
| Остальные `audio/` | Модели, валидация, озвучивание, речь, сведение, кодирование |

Объекты получают зависимости через конструкторы. Обработчик диалога не создаёт соединений и HTTP-клиентов. AsyncExitStack закрывает ресурсы при выходе и исключениях. SqliteConversationStore объединяет связанные SQL-операции над одной базой; сборка контекста вынесена из хранения.

Классы используются для компонентов с состоянием, ресурсами или отдельным жизненным циклом. Чистые преобразования остаются функциями. Задания и результаты описаны dataclass, музыкальные JSON-структуры — TypedDict. Protocol позволяет подменять зависимости без обязательного наследования.

## Паттерны и аудио

Adapter используется для интеграций, Strategy — для композиторов, Facade — для управления аудиозаданием. Стратегия выбирается небольшой функцией. Отдельной иерархии фабрик, глобального Singleton или контейнера зависимостей нет.

Основной бот не импортирует NumPy, ONNX Runtime и Piper при запуске. Worker загружает нужные библиотеки, выполняет одно задание и завершается до отправки аудио. Он запускается через `python -m semen_banan.audio.worker`; при отмене и таймауте останавливается дерево процессов. Кеш моделей ограничен процессом worker или ручного инструмента.

## Перенос и совместимость

Целевая версия — Python 3.13. Зависимости и настройки инструментов собраны в pyproject.toml; requirements-файлы оставлены как совместимые команды установки пакета.

База, интервалы, .env и модели остаются на прежних путях. Схема SQLite сохранена. Перед переносом сохранены текущие исходники, база через SQLite backup API и state.json в .runtime/backups/.

Старые корневые Python-модули заменены пакетами, тесты перенесены в tests/, установщик и сравнения — в tools/. Тестовый синтезатор render_wav, не использовавшийся рабочим аудиопутём, удалён; кодирование проверяется настоящим аудиопроцессом. Результаты старых экспериментов и неиспользуемый TimGM6mb убраны из рабочей структуры в локальную резервную копию. Основной банк GeneralUser GS и лицензии сохранены.

## Проверки и следующий этап

Проверки покрывают обработку сообщений, контекст, восстановление очереди, контракт Gateway, voice, изоляцию моделей и остановку процессов. Диагностические тесты проверяют создание музыки без Telegram и изменения рабочих данных. Реальный Gateway проверяется отдельными командами диагностики.

Следующий этап — логирование: единая конфигурация, время и контекст событий, уровни, ротация, диагностика worker и исключение секретов. На текущем этапе сохранено прежнее поведение журналов; логгеры получают имена модулей.

## Контракт маршрутизации

`OpenClawClient.classify()` передаёт сообщение, контекст и метаданные отдельной системной инструкции из раздела `[routing]` в `resources/prompts.toml`. `MessageRouter` проверяет результат и при необходимости один раз запрашивает исправление JSON. `ConversationService` применяет решение; `MusicGenerator` получает уже выбранные параметры через обязательный аргумент `options`, без анализа текста.

Пример ответа маршрутизатора:

```json
{
  "mode": "music",
  "trigger": "direct",
  "parameters": {"composer": "nanomaestro", "drums": true, "speech": false},
  "style_request": null
}
```

У `ignore` и `text` параметры равны null. Для `ignore` тип обращения — `none`; для ответов допустимы `direct`, `chain`, `request` и `banana`. Банановый режим допускает только текст и не меняет характер. `style_request` — отдельная инструкция до 500 символов либо null.

В очередь передаётся сообщение с внутренним полем `_routing`, содержащим проверенное решение. На повторе оно разбирается тем же валидатором. Старые задания без поля проходят классификацию, а UPSERT обновляет не только время, но также тип и JSON задания. Входящее сообщение сначала сохраняется для контекста; после определения обращения его признак цепочки может быть повышен, но не сброшен.

## Типы и оформление

`conversation/models.py` описывает контекст, личность бота, метаданные маршрутизации и строки истории. `audio/models.py` описывает ноты и аудиозадания. Тип стереосэмплов вынесен в `audio/types.py` и подключается через `TYPE_CHECKING`, чтобы аннотации не загружали NumPy в основной процесс. Тип PiperVoice также импортируется только для проверки типов.

`PromptCatalog` читает единый TOML-файл, проверяет обязательные строки и подстановки. Каталог можно передать клиенту OpenClaw через конструктор, а стандартный экземпляр кешируется. Рабочие данные и схема SQLite при этом не меняются. Правила оформления описаны в [code-style.md](code-style.md).
