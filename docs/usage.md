# Работа с SemenBanan

## Установка вручную

Проект рассчитан на Python 3.13. На Windows используй `start.ps1` или установи окружение вручную из корня проекта:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[music]"
.\.venv\Scripts\python.exe tools/setup_assets.py
.\.venv\Scripts\python.exe -m semen_banan --check
.\.venv\Scripts\python.exe -m semen_banan
```

Создай `.env` по `.env.example` и заполни значения до проверки. На Linux/macOS используй `python3.13`, окружение `.venv/bin/python` и установи FluidSynth средствами ОС. FFmpeg ищется в системе, затем через `imageio-ffmpeg`.

Установщик загружает закреплённые версии ресурсов с проверкой контрольных сумм. Веса NanoMaestro и словарь устанавливаются согласованной парой. Загрузок моделей во время обработки сообщений нет. Лицензии перечислены в [THIRD_PARTY.md](../THIRD_PARTY.md).

## OpenClaw

В конфигурации Gateway включи `gateway.http.endpoints.chatCompletions.enabled=true` и настрой агента `semyon`. Запросы направляются на `/v1/chat/completions`, модель — `openclaw/semyon`. Telegram-токен и токен Gateway — разные секреты. Отдельный ключ поставщика модели в Python не нужен.

Для агента отключи инструменты и heartbeat. Не подключай тот же Telegram-токен к Telegram-каналу OpenClaw: обновления принимает Python-приложение. Сохрани существующие настройки других агентов при настройке Gateway.

## Конфигурация

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `ALLOWED_CHAT_IDS` | ID разрешённых групп через запятую |
| `OPENCLAW_BASE_URL` | HTTP(S)-адрес Gateway; суффикс `/v1` допустим |
| `OPENCLAW_GATEWAY_TOKEN` | Токен или пароль Gateway |
| `OPENCLAW_AGENT_ID` | Агент, по умолчанию `semyon` |
| `COOLDOWN_SECONDS` | Интервал между ответами в группе, по умолчанию 10 секунд |
| `BANANA_PROBABILITY` | Вероятность реакции на бананы, по умолчанию 0.25 |
| `REQUEST_TIMEOUT` | Время ожидания модели, по умолчанию 90 секунд |
| `AUDIO_TIMEOUT_SECONDS` | Время ожидания аудиопроцесса, по умолчанию 90 секунд |

`SEMEN_BANAN_HOME` можно задать в окружении процесса до запуска: это каталог `.env`, базы, состояния и `assets/`. В исходном checkout он определяется автоматически, `start.ps1` задаёт его явно. При установке обычного wheel без этой переменной используется текущий каталог. Относительный `--output` отсчитывается от рабочего каталога команды.

После изменения `.env` или персонажа перезапусти бота. Все инструкции модели хранятся в `src/semen_banan/resources/prompts.toml` и включаются в пакет. Характер персонажа — в разделе `[persona]`, маршрутизация — `[routing]`, сочинение — `[composition]`, аранжировка — `[arrangement]`. Проверочные запросы и шаблоны инструментов находятся в `[diagnostics]` и `[comparison]`; служебное пояснение усечённого контекста — в `[context]`.

## Диагностические режимы

- `--check` выполняет `getMe` и пробный запрос Gateway. Музыку не генерирует.
- `--check-gateway` делает только запрос Gateway; Telegram-токен не требуется.
- `--check-music` проверяет общий с ботом путь: определение режима и параметров через LLM, сочинение, аранжировка, генерация аудио, сведение и кодирование OGG/Opus. Telegram-токен и список групп не нужны. История, очередь и интервалы не изменяются. Выходной файл по умолчанию — `.runtime/checks/music.ogg`; успешная повторная проверка заменяет его.
- `--discover-chats` читает обновления Telegram и выводит ID групп при любом сообщении группы, в том числе `/id`. Запускай после остановки обычного бота.

Проверки `--check`, `--check-gateway` и `--check-music` не отправляют сообщения в Telegram. Они могут расходовать лимиты поставщика модели. Диагностику запускай в переднем плане, без `-Background`.

```powershell
.\.venv\Scripts\python.exe -m semen_banan --check-music --request "Сыграй только пианино" --output .runtime/checks/piano.ogg
.\.venv\Scripts\python.exe -m semen_banan --check-music --request "Сыграй через NanoMaestro" --output .runtime/checks/nano.ogg
```

По умолчанию проверяется партитура OpenClaw с пианино, барабанами и речью. Для проверки локального композитора явно укажи NanoMaestro. Готовый файл можно прослушать любым плеером с поддержкой OGG/Opus. Код завершения 0 означает успех, 1 — рабочую ошибку, 2 — ошибку аргументов командной строки. Если генерация завершилась ошибкой, предыдущий файл не заменяется.

## Определение режима через LLM

После проверок разрешённой группы, автора и возраста каждое допустимое текстовое сообщение отправляется в OpenClaw для классификации. Модель получает текст, имя автора, контекст соответствующей темы или цепочки (до 8000 символов), личность бота, признаки ответа/упоминания/цепочки и сохранённые пожелания к характеру.

Она возвращает JSON с режимом `ignore`, `text`, `music` или `image`, типом обращения и параметрами. Для музыки доступны композитор `score` или `nanomaestro`, состав инструментов, барабаны, речь, точная длительность, темп и громкость дорожек. Изменение характера передаётся отдельной инструкцией `style_request`; его можно совместить с музыкальным запросом. В коде нет регулярных выражений для определения этих намерений.

Обычные разговоры участников модель должна помечать `ignore`. Обращение, просьбу создать музыку, уточнение предыдущей записи и просьбу изменить характер она определяет по смыслу. Сообщения из чужих групп, от ботов и анонимных администраторов, личные сообщения и слишком старые новые сообщения в классификатор не попадают.

JSON строго проверяется: неизвестные режимы, параметры, композиторы и неправильные типы отклоняются. При неверном JSON делается одна попытка исправления; локального угадывания режима нет. При сетевой ошибке или двух неверных ответах сообщение ставится на повтор через 30 секунд с общим сроком жизни 10 минут. Если оно окажется обычным разговором, после восстановления модели будет проигнорировано.

Решение сохраняется в JSON отложенного задания, включая музыкальные параметры или параметры картинки. Повтор генерации или перезапуск не вызывает повторную классификацию такого задания и повторное сохранение характера. Задания от прежней версии без решения классифицируются при следующей попытке. Формат рабочих таблиц SQLite сохранён; обновление существующего задания также сохраняет его новые параметры.

Это дополнительный запрос к модели для каждого допустимого текстового сообщения, в том числе для решения промолчать. Он увеличивает задержку и расход лимитов Gateway. Вероятность бананового ответа, интервалы, доступ к группам и ограничения длительности музыки по-прежнему контролируются приложением.

## Поведение

Бот отвечает на новые сообщения разрешённых групп: обращения по имени, упоминания, ответы в цепочке и музыкальные просьбы. На банановые сообщения реагирует с заданной вероятностью. Личные сообщения, другие боты, правки и сообщения старше двух минут игнорируются.

Прямые обращения и музыкальные просьбы во время общего интервала группы ожидают в SQLite-очереди; банановые сообщения пропускаются. Очередь переживает перезапуск, обращения старше 10 минут удаляются. После сетевой ошибки прямое обращение остаётся для повтора. При запуске бот отбрасывает накопленные обновления Telegram.

Контекст цепочки ограничен 60 000 символов; для сообщения вне цепочки используются последние 12 реплик темы. Явные просьбы изменить характер сохраняются для группы. Данные контекста передаются в Gateway и поставщику модели.

Основная музыкальная фраза состоит из четырёх тактов. Для заданной длительности она повторяется до нужной длины, затем запись точно ограничивается по времени с коротким затуханием. «Только пианино» отключает барабаны и речь; «без речи» и «без барабанов» отключают отдельные дорожки. NanoMaestro продолжает начальный такт, созданный по запросу через Gateway. Локальная генерация NanoMaestro ограничена 20 секундами. При слишком коротком результате разрешена одна повторная попытка в пределах того же бюджета.

## Данные и завершение

`memory.sqlite3` хранит историю, характер и очередь; `state.json` — интервалы. Форматы при рефакторинге сохранены. SQLite может создавать `-wal` и `-shm`: это рабочие файлы базы.

Для каждого музыкального ответа запускается отдельный процесс. Он получает JSON через stdin, создаёт аудио во временном каталоге и завершается до отправки записи. Токены Telegram и Gateway исключаются из его окружения. При отмене или таймауте останавливается дерево процессов, временный каталог очищается.

Фоновый запуск хранит PID в `.runtime.pid`, вывод — в `.runtime/stdout.log` и `.runtime/stderr.log`. `stop.ps1` проверяет принадлежность процесса проекту и останавливает всё дерево.

## Если не работает

- Нет ответов: проверь разрешённые группы, privacy и общий интервал. Используй обращение по имени.
- `401`: проверь токен соответствующего сервиса и авторизацию модели.
- `404` Gateway: проверь endpoint и агента.
- `409` Telegram: останови другой экземпляр или прежний webhook.
- Ошибка музыкальных ресурсов: повтори установку `tools/setup_assets.py`, проверь FluidSynth и зависимости группы `music`.

## Редактирование промптов

Единая точка настройки — [prompts.toml](../src/semen_banan/resources/prompts.toml). После изменения перезапусти бота: каталог загружается и кешируется на время работы процесса.

Не удаляй подстановки `${total_beats}`, `${last_speech_beat}` и `${speech_guidance}` из шаблона аранжировки. У шаблонов сравнения свой фиксированный набор подстановок; загрузчик проверяет его до запроса модели. Фигурные скобки JSON не требуют экранирования. Тексты запросов подставляются однократно и не становятся вложенными шаблонами.

Длинные инструкции TOML могут использовать обратную косую черту в конце строки для переноса исходника без добавления перевода строки в промпт. Обычные многострочные блоки сохраняют абзацы. Ошибки TOML, отсутствующие разделы и неверные подстановки возвращают понятную ошибку загрузки.

## Точные параметры музыкальной записи

| Параметр | Допустимые значения | Если не указан |
|---|---|---|
| Длительность | Целое число от 5 до 60 секунд | Исходные четыре такта с естественным затуханием |
| Темп | Целое число от 60 до 180 BPM | Выбирает композитор LLM |
| Инструменты | От одного до четырёх разных тембров | Пианино |
| Громкость дорожки | Целое число от 0 до 100 процентов | 100% |
| Общая громкость | Целое число от 0 до 100 процентов | 100% |

Тембры: пианино, электропианино, акустическая гитара, бас, струнные, синтезатор, флейта и орган, а также чистая и приглушённая электрогитары, электрогитары с овердрайвом и дисторшном, электробас с медиаторной атакой. Барабаны и разговорная речь включаются отдельно. Бас и электробас формируются из нижних нот аккордов; остальные выбранные тембры озвучивают музыкальную фразу. Это локальные инструменты установленного банка GeneralUser GS, дополнительные модели не нужны.

Громкость можно задавать отдельно каждому инструменту, барабанам и речи. Проценты задают относительный коэффициент амплитуды дорожки; общая громкость применяется после сведения и не отменяется нормализацией. Ноль означает тишину. Ограничитель пиков защищает микс от перегрузки; проценты не являются абсолютными децибелами или настройкой системной громкости.

Примеры:

- «Семён, сделай 30 секунд при 85 BPM, гитара и бас, без речи. Бас 40%, барабаны 25%, общая громкость 70%».
- «Сыграй ровно 5 секунд при 180 BPM только на электропианино, общая громкость 20%».
- «Теперь тот же состав, но на 45 секунд и без ударных» — параметры уточняются с учётом контекста.

LLM возвращает параметры, а приложение проверяет типы и диапазоны, выставляет реальный темп синтеза и точную длину аудио. При просьбе за пределами возможностей маршрутизатору предписано выбрать ближайшую разрешённую границу. На границе процесса параметры проверяются повторно. Длинная запись сейчас повторяет исходную четырёхтактовую фразу; отдельная генерация куплетов и припевов не добавлялась.

Параметры сохраняются в очереди вместе с выбранным режимом и переживают перезапуск. Старый формат с composer/drums/speech остаётся совместимым.

Полная проверка без публикации в Telegram:

```powershell
.\.venv\Scripts\python.exe -m semen_banan --check-music --request "Семён, 30 секунд при 85 BPM, гитара и бас, без речи, бас 40 процентов" --output .runtime/checks/custom-song.ogg
```


### Настройки локального голоса

Если в записи нужна речь, LLM возвращает `voice_settings` в музыкальных параметрах:

```json
{"voice":"eugene","speed":0.85,"pitch_semitones":-3,"effect":"echo","effect_amount":25}
```

По умолчанию используется Silero v5.6 с голосом `eugene`. Также доступны `aidar`, `baya`, `kseniya`, `xenia`; прежний Piper доступен как `denis`. Скорость `speed` — от 0.75 до 1.5, высота `pitch_semitones` — от −6 до +6 полутонов с сохранением скорости. Эффекты: `none` (обычный), `robot`, `telephone`, `echo`, `reverb`, `chorus`. Интенсивность `effect_amount` — 0–100% подмешанного эффекта; ноль отключает его. Одновременно выбирается один эффект. Громкость речи задаётся прежним `volumes.speech`.

Пример: «Семён, создай музыку с речью. Голос ниже на три полутона, скорость 0.85, лёгкое эхо». Без просьбы изменить звучание используются голос Eugene без эффектов и стандартная скорость. Голос синтезируется и обрабатывается локально; это речь поверх музыки. Хвосты эффектов обрезаются на границе явно заданной длительности записи. Настройки переживают перезапуск вместе с очередью.


Состав инструментов LLM выбирает по жанру, настроению и контексту, если пользователь не задал его явно. Для тяжёлых жанров доступны `electric_guitar`, `muted_guitar`, `overdriven_guitar`, `distortion_guitar`, `electric_bass`; прежний `guitar` остаётся акустической гитарой. Просьбы «только флейта», «без гитары» имеют приоритет над жанром. Например: «Семён, сыграй тяжёлый металлический рифф на 45 секунд, без речи». Это тембры General MIDI: реалистичное исполнение группы и вокал не гарантируются; запись по-прежнему повторяет одну четырёхтактовую фразу.


### Баланс речи и инструментала

Во время активной речи инструменты плавно приглушаются максимум на 20% амплитуды (около 1.94 дБ), барабаны — на 10% (около 0.92 дБ). Тихая речь вызывает меньшее приглушение, а выключенная — не вызывает его. Раньше снижение достигало 68% и 50%, поэтому инструментал заметно проваливался. Баланс одинаков для стандартного и настраиваемого состава; пользовательская громкость дорожек сохраняется.

Silero работает на CPU через PyTorch, с локальным файлом `assets/speech/silero-v5_6-ru.pt`. Во время синтеза загрузок из сети нет. Это синтез речи, а не пение по нотам. Исходная модель: [Silero Models](https://github.com/snakers4/silero-models), лицензия модели — CC BY-NC-SA 4.0; копия сохраняется рядом с моделью.


## Генерация картинок

Примеры: «Семён, нарисуй космического кота акварелью», «Сделай вертикальный постер с бананом-гитаристом без текста». Ответом на предыдущую картинку можно попросить новый вариант: «Сделай темнее и в другом стиле». Модель получает описание предыдущего результата из истории, а не исходные пиксели: это новая генерация, а не редактирование фотографии.

Режим `image` выбирает LLM. Она возвращает:

```json
{"mode":"image","trigger":"direct","parameters":{"prompt":"Самостоятельное описание сюжета, стиля и композиции","size":"1024x1024","caption":"Краткая подпись"},"style_request":null}
```

Размеры: квадрат `1024x1024`, горизонтальный `1536x1024`, вертикальный `1024x1536`. Это пожелания провайдеру; фактическое разрешение может отличаться. Создаётся одна новая картинка. Анализ и редактирование присланных фото пока не поддерживаются. Режим музыки остаётся отдельным.

Генерацию выполняет установленный OpenClaw через `infer image generate`, используя сохранённую авторизацию агента `OPENCLAW_AGENT_ID`. Имена исполняемых файлов, модель и параметры запуска задаёт конфигурация приложения; LLM задаёт только описание, размер и подпись. Командная оболочка для текста запроса не используется. Политики инструментов текстового агента менять не требуется; отправляет фото Python-бот, Telegram-канал OpenClaw для этого не нужен.

Настройки `.env`:

```dotenv
IMAGE_TIMEOUT_SECONDS=180
OPENCLAW_IMAGE_MODEL=openai/gpt-image-2
OPENCLAW_IMAGE_EXECUTABLE=openclaw
OPENCLAW_IMAGE_WSL_DISTRO=
```

Для текущей установки на Windows:

```dotenv
OPENCLAW_IMAGE_WSL_DISTRO=OpenClawGateway
OPENCLAW_IMAGE_EXECUTABLE=/usr/local/bin/openclaw
```

На Linux оставь дистрибутив WSL пустым и обеспечь доступ к `openclaw` в PATH либо укажи абсолютный путь. В Windows результат читается через `\\wsl.localhost\<дистрибутив>\tmp`, поэтому монтирование диска проекта в WSL не требуется. Авторизацию и наличие модели можно проверить в нужной среде командой `openclaw infer image providers --agent semyon --json`. Конкретная доступность и стоимость зависят от провайдера и авторизации OpenClaw.

Проверка без отправки в Telegram:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 --check-image --request "Семён, нарисуй кота в космосе" --output .runtime/checks/cat.jpg
```

Результат проверяется и подготавливается как JPEG: прозрачность заменяется белым фоном, длинная сторона ограничивается 2048 пикселями, размер файла — 10 МБ. Фото отправляется с подписью ответом на исходное сообщение в ту же тему группы. Описание сохраняется в истории для уточнений. Готовые файлы в `.runtime/images` хранятся семь суток; при сетевой ошибке Telegram очередь повторно отправляет тот же файл. Ошибка самой генерации показывается пользователю без автоматических повторных запросов к провайдеру. Таймаут настраивается от 10 до 600 секунд.


## Сведения о группе и фотографии участников

Справочник `group.toml` содержит имена, варианты обращения, роли и факты из поста владельца группы. Он загружается при запуске; после редактирования перезапусти бота. Модель не меняет этот файл. Справочник добавляется в `group_profile` при каждом обращении к LLM: маршрутизация, текстовый ответ, партитура и аранжировка. При генерации изображений сведения также включаются в описание для провайдера.

Фотографии хранятся отдельно в `assets/participants/`, в следующем подтверждённом владельцем порядке:

1. Кравчук Артём — барабанщик, фирменная лягушачья шапка.
2. Фам Хоанг Вьет — ритм-гитарист, выбрал рок вместо кей-попа.
3. Кузнецов Кирилл — басист, клавишник и бэк-вокалист, всю жизнь прожил в Питере.
4. Трикула Артём — соло-гитарист, «с великой мудростью в волосах».
5. Ёшин Игорь — вокалист и автор песен, «чуть поёт, чуть читает».

Оригиналы фотографий остаются неизменными. Для передачи готовятся JPEG с длинной стороной до 1024 пикселей. Каталог `assets/` исключён из Git; фотографии нужно переносить отдельно при развёртывании. Файл `group.toml` находится рядом с `.env` и не входит в установленный Python-пакет. Если его нет, справочник пуст; запрос фото в таком случае возвращает понятную ошибку.

Дополнительное поле JSON маршрутизации:

```json
{"mode":"image","trigger":"direct","parameters":{"prompt":"Фам Хоанг Вьет с бананом на репетиции","size":"1024x1024","caption":"Банановая репетиция"},"style_request":null,"load_participant_photos":true}
```

`load_participant_photos` — строго булево значение. `false` означает, что содержимое фотографий не загружается и не передаётся модели. `true` загружает все пять подписанных фото; частичный выбор пока не поддерживается. Сначала маршрутизатор видит только текстовый справочник и решает, нужны ли фото для дальнейшего ответа. Решение сохраняется в очереди; в старых заданиях отсутствие поля означает `false`.

Примеры: «Нарисуй Вьета с бананом» требует фото; «Кто играет на басу?» и «Нарисуй банан на сцене» — нет. Для неоднозначного «Нарисуй Артёма» модель должна уточнить фамилию или роль. Явная просьба не использовать фотографии имеет приоритет.

При текстовом ответе фотографии отправляются в модель как подписанные `image_url` с данными JPEG. При рисунке OpenClaw получает все пять файлов через `infer image edit --file ...`; имена сопоставлены номерам фото в описании. Генератору указано изображать только запрошенных людей, а не всех, чьи фотографии приложены. Это использование заранее сохранённых образцов; редактирование произвольных фотографий из Telegram по-прежнему не поддерживается.

Фото передаются настроенному провайдеру OpenClaw только при положительном флаге. Отсутствующее или повреждённое фото не пропускается молча: бот сообщает об ошибке. Личности и роли берутся из справочника владельца, а не определяются по внешности.
