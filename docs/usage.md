# Работа с SemenBanan

## Установка вручную

Проект рассчитан на Python 3.13. На Windows используй `start.ps1` или установи окружение вручную из корня проекта:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[music]"
.\.venv\Scripts\python.exe tools/setup_assets.py
.\.venv\Scripts\python.exe -m semen_banan --check
.\.venv\Scripts\python.exe -m semen_banan
```

Создай `.env` по `.env.example` и заполни значения до проверки. На Linux/macOS используй `python3.13`, окружение `.venv/bin/python` и установи FluidSynth средствами ОС. FFmpeg ищется в системе, затем через `imageio-ffmpeg`.

Установщик загружает закреплённые версии ресурсов с проверкой контрольных сумм. Веса NanoMaestro и словарь устанавливаются согласованной парой. Загрузок моделей во время обработки сообщений нет. Лицензии перечислены в [THIRD_PARTY.md](../THIRD_PARTY.md).

## OpenClaw

В конфигурации Gateway включи `gateway.http.endpoints.chatCompletions.enabled=true` и настрой агента `semyon`. Запросы направляются на `/v1/chat/completions`, модель — `openclaw/semyon`. Telegram-токен и токен Gateway — разные секреты. Отдельный ключ поставщика модели в Python не нужен.

Для агента отключи инструменты и heartbeat. Не подключай тот же Telegram-токен к Telegram-каналу OpenClaw: обновления принимает Python-приложение. Сохрани существующие настройки других агентов при настройке Gateway.

## Конфигурация

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `ALLOWED_CHAT_IDS` | ID разрешённых групп через запятую |
| `OPENCLAW_BASE_URL` | HTTP(S)-адрес Gateway; суффикс `/v1` допустим |
| `OPENCLAW_GATEWAY_TOKEN` | Токен или пароль Gateway |
| `OPENCLAW_AGENT_ID` | Агент, по умолчанию `semyon` |
| `COOLDOWN_SECONDS` | Интервал между ответами в группе, по умолчанию 10 секунд |
| `BANANA_PROBABILITY` | Вероятность реакции на бананы, по умолчанию 0.25 |
| `REQUEST_TIMEOUT` | Время ожидания модели, по умолчанию 90 секунд |
| `AUDIO_TIMEOUT_SECONDS` | Время ожидания аудиопроцесса, по умолчанию 90 секунд |

`SEMEN_BANAN_HOME` можно задать в окружении процесса до запуска: это каталог `.env`, базы, состояния и `assets/`. В исходном checkout он определяется автоматически, `start.ps1` задаёт его явно. При установке обычного wheel без этой переменной используется текущий каталог. Относительный `--output` отсчитывается от рабочего каталога команды.

После изменения `.env` или персонажа перезапусти бота. Текст персонажа хранится в `src/semen_banan/resources/persona.txt` и включается в пакет.

## Диагностические режимы

- `--check` выполняет `getMe` и пробный запрос Gateway. Музыку не генерирует.
- `--check-gateway` делает только запрос Gateway; Telegram-токен не требуется.
- `--check-music` проверяет общий с ботом путь: сочинение, аранжировка, генерация аудио, сведение и кодирование OGG/Opus. Telegram-токен и список групп не нужны. История, очередь и интервалы не изменяются. Выходной файл по умолчанию — `.runtime/checks/music.ogg`; успешная повторная проверка заменяет его.
- `--discover-chats` читает обновления Telegram и выводит ID групп при любом сообщении группы, в том числе `/id`. Запускай после остановки обычного бота.

Проверки `--check`, `--check-gateway` и `--check-music` не отправляют сообщения в Telegram. Они могут расходовать лимиты поставщика модели. Диагностику запускай в переднем плане, без `-Background`.

```powershell
.\.venv\Scripts\python.exe -m semen_banan --check-music --request "Сыграй только пианино" --output .runtime/checks/piano.ogg
.\.venv\Scripts\python.exe -m semen_banan --check-music --request "Сыграй через NanoMaestro" --output .runtime/checks/nano.ogg
```

По умолчанию проверяется партитура OpenClaw с пианино, барабанами и речью. Для проверки локального композитора явно укажи NanoMaestro. Готовый файл можно прослушать любым плеером с поддержкой OGG/Opus. Код завершения 0 означает успех, 1 — рабочую ошибку, 2 — ошибку аргументов командной строки. Если генерация завершилась ошибкой, предыдущий файл не заменяется.

## Поведение

Бот отвечает на новые сообщения разрешённых групп: обращения по имени, упоминания, ответы в цепочке и музыкальные просьбы. На банановые сообщения реагирует с заданной вероятностью. Личные сообщения, другие боты, правки и сообщения старше двух минут игнорируются.

Прямые обращения и музыкальные просьбы во время общего интервала группы ожидают в SQLite-очереди; банановые сообщения пропускаются. Очередь переживает перезапуск, обращения старше 10 минут удаляются. После сетевой ошибки прямое обращение остаётся для повтора. При запуске бот отбрасывает накопленные обновления Telegram.

Контекст цепочки ограничен 60 000 символов; для сообщения вне цепочки используются последние 12 реплик темы. Явные просьбы изменить характер сохраняются для группы. Данные контекста передаются в Gateway и поставщику модели.

Музыкальный запрос создаёт четыре такта. «Только пианино» отключает барабаны и речь; «без речи» и «без барабанов» отключают отдельные дорожки. NanoMaestro продолжает начальный такт, созданный по запросу через Gateway. Локальная генерация NanoMaestro ограничена 20 секундами. При слишком коротком результате разрешена одна повторная попытка в пределах того же бюджета.

## Данные и завершение

`memory.sqlite3` хранит историю, характер и очередь; `state.json` — интервалы. Форматы при рефакторинге сохранены. SQLite может создавать `-wal` и `-shm`: это рабочие файлы базы.

Для каждого музыкального ответа запускается отдельный процесс. Он получает JSON через stdin, создаёт аудио во временном каталоге и завершается до отправки записи. Токены Telegram и Gateway исключаются из его окружения. При отмене или таймауте останавливается дерево процессов, временный каталог очищается.

Фоновый запуск хранит PID в `.runtime.pid`, вывод — в `.runtime/stdout.log` и `.runtime/stderr.log`. `stop.ps1` проверяет принадлежность процесса проекту и останавливает всё дерево.

## Инструменты сравнения

Поддерживаемые ручные инструменты вынесены из корня:

```powershell
.\.venv\Scripts\python.exe tools/compare_music.py --output comparison --bars 16 --tempo 110
.\.venv\Scripts\python.exe tools/compare_arrangement.py --source comparison/comparison.json --output comparison/full
```

Это эксперименты без отправки в Telegram; модели могут оставаться в памяти до завершения инструмента. Результаты не включаются в Git.

## Если не работает

- Нет ответов: проверь разрешённые группы, privacy и общий интервал. Используй обращение по имени.
- `401`: проверь токен соответствующего сервиса и авторизацию модели.
- `404` Gateway: проверь endpoint и агента.
- `409` Telegram: останови другой экземпляр или прежний webhook.
- Ошибка музыкальных ресурсов: повтори установку `tools/setup_assets.py`, проверь FluidSynth и зависимости группы `music`.

## Проверки разработки

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[music,dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests/unit -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m ruff check src tests tools
.\.venv\Scripts\python.exe -m ruff format --check src tests tools
.\.venv\Scripts\python.exe -m mypy
```

Автоматические тесты не используют настоящий Telegram или Gateway. Интеграционные тесты запускают локальные аудиоинструменты и процессы; при отсутствии моделей отдельные проверки пропускаются. В интеграционной проверке worker используется фиксированный seed для воспроизводимого результата NanoMaestro.
